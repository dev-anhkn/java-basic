**Strategy Pattern – Mẫu chiến lược**- Thuộc nhóm: Behavioral Pattern- Mục đích: Cho phép bạn định nghĩa một họ các thuật toán (hoặc hành vi), đóng gói từng thuật toán, và làm cho chúng có thể hoán đổi cho nhau mà không thay đổi code sử dụng chúng.**Vấn đề (Problem)**Bạn có một class thực hiện một hành vi (behavior), nhưng bạn muốn thay đổi hành vi đó một cách linh hoạt mà không phải sửa đổi class gốc.- Ví dụ: Một nhân vật trong game có thể “di chuyển” bằng nhiều cách khác nhau: đi bộ, bay, bò, v.v. Bạn không muốn viết if-else trong class Character cho từng cách di chuyển.**Ý tưởng (Intent)**Tách riêng phần hành vi (behavior) thành các class riêng biệt, sau đó truyền hành vi này vào class sử dụng, để có thể thay đổi hành vi trong runtime.
