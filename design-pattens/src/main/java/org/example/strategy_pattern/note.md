1. VẤN ĐỀ (PROBLEM)   Bạn có một chức năng có nhiều cách thực hiện khác nhau (thuật toán, hành vi).   Tuy nhiên:    - Không muốn viết nhiều if-else để xử lý các trường hợp đó    - Muốn chuyển đổi cách thực hiện linh hoạt    - Muốn tách rời thuật toán khỏi logic chính2. MỤC ĐÍCH (INTENT)   Cho phép bạn định nghĩa một họ các thuật toán (strategies), đóng gói từng thuật toán trong một class riêng biệt, và   hoán đổi linh hoạt giữa chúng mà không ảnh hưởng đến code sử dụng chúng.3. THÀNH PHẦN    - Strategy: Interface định nghĩa hành vi chung    - ConcreteStrategy; Cài đặt các thuật toán cụ thể    - Context: Sử dụng và chứa một Strategy, gọi execute()4. KHI NÀO DÙNG (APPLICABILITY)    - Có nhiều cách xử lý một hành động    - Bạn cần chuyển đổi hành vi động theo runtime    - Muốn loại bỏ if-else hoặc switch-case dài dòng    - Cần mở rộng thuật toán mới dễ dàng (OCP)5. ƯU ĐIỂM (ADVANTAGES)    - ✅ Tuân thủ Open/Closed Principle: Thêm thuật toán mới không sửa code cũ    - ✅ Tách biệt logic: Từng thuật toán độc lập, dễ test    - ✅ Dễ mở rộng: Mỗi thuật toán nằm trong class riêng    - ✅ Runtime flexibility: Có thể đổi thuật toán trong lúc chạy6. NHƯỢC ĐIỂM (DISADVANTAGES)    - ❌ Nhiều class: Mỗi chiến lược cần một class riêng    - ❌ Cần biết chọn cái nào phù hợp: Có thể phải map theo Enum, config    - ❌ Không hợp nếu logic quá đơn giản: Tách ra class riêng sẽ thừa7. VÍ DỤ THỰC TẾ    - Thanh toán: Cổng thanh toán: Visa, Momo, PayPal…    - Tính phí giao hàng: Các cách tính theo loại dịch vụ: Express, Standard, Same-day    - Tính lương nhân viên: Theo giờ, theo sản phẩm, theo tháng    - Khuyến mãi: Giảm theo % / theo tiền / freeship    - AI / Game: Chiến lược tấn công: Rambo, phòng thủ, lẩn trốn---------------------------------------------------------------------**Strategy Pattern – Mẫu chiến lược**- Thuộc nhóm: Behavioral Pattern- Mục đích: Cho phép bạn định nghĩa một họ các thuật toán (hoặc hành vi), đóng gói từng thuật toán, và làm cho chúng có  thể hoán đổi cho nhau mà không thay đổi code sử dụng chúng.**Vấn đề (Problem)**Bạn có một class thực hiện một hành vi (behavior), nhưng bạn muốn thay đổi hành vi đó một cách linh hoạt mà không phảisửa đổi class gốc.- Ví dụ: Một nhân vật trong game có thể “di chuyển” bằng nhiều cách khác nhau: đi bộ, bay, bò, v.v. Bạn không muốn viết  if-else trong class Character cho từng cách di chuyển.**Ý tưởng (Intent)**Tách riêng phần hành vi (behavior) thành các class riêng biệt, sau đó truyền hành vi này vào class sử dụng, để có thểthay đổi hành vi trong runtime.
