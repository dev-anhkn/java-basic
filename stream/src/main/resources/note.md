Lý do tại sao các lập trình viên backend (dev BE) lại thích sử dụng Stream() trong Java?1. Lập trình hàm (Functional programming) hiện đại, code ngắn gọn   - Stream giúp viết code xử lý collection (List, Set, Map, v.v.) ngắn gọn, dễ đọc và dễ bảo trì hơn so với vòng lặp truyền thống.    - Bạn có thể filter, map, sort, group, reduce… chỉ trong 1 dòng lệnh.   - List<String> names = users.stream()     .filter(u -> u.getAge() > 18)     .map(User::getName)     .sorted()     .collect(Collectors.toList());2. Xử lý dữ liệu hiệu quả hơn    - Stream có thể lười biếng (lazy), tức là chỉ thực hiện tính toán khi cần thiết (ví dụ khi gọi collect, findFirst, forEach…), tiết kiệm tài nguyên.    - Hỗ trợ xử lý song song (parallel stream) dễ dàng để tận dụng đa nhân của CPU:   - list.parallelStream()     .filter(x -> x.isActive())     .count();3. Có nhược điểm gì không?   - Nếu xử lý cực nhiều dữ liệu, stream không phải lúc nào cũng nhanh hơn for truyền thống.   - Không phù hợp cho code có yêu cầu tối ưu hoá hiệu năng ở mức thấp nhất (low level).Nhưng đa số các bài toán BE đều phù hợp dùng Stream, trade-off giữa tốc độ và dễ bảo trì/chuyển đổi là xứng đáng.1. Parallel Stream là gì?   •	Parallel Stream là một tính năng của Java Stream API, cho phép xử lý dữ liệu song song (parallel processing) thay vì tuần tự (sequential).   •	Khi gọi parallelStream() hoặc .parallel(), Java sẽ tự động chia nhỏ công việc và thực hiện trên nhiều thread khác nhau, tận dụng nhiều core CPU.
