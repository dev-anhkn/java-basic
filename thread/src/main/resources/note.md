Tại sao trong lập trình đồng thời (concurrent programming), người ta lại nói nhiều về Thread hoặc bắt đầu từ Thread?1. Thread là nền tảng cơ bản của lập trình đồng thời	•	Thread (luồng) là đơn vị cơ bản nhất để thực hiện nhiều tác vụ cùng lúc trong một tiến trình (process).	•	Mỗi thread có thể thực thi một đoạn mã độc lập, chia sẻ tài nguyên với các thread khác trong cùng tiến trình.	•	Tất cả các mô hình lập trình đồng thời hiện đại (thread pool, actor, coroutine, async/await…) đều xây dựng hoặc lấy cảm hứng từ cơ chế thread truyền thống. 2. Vì sao lại bắt đầu từ thread?a. Là khái niệm gốc, dễ hình dung	•	Khi nói về lập trình đồng thời, thread là đơn vị “thực thi song song” mà lập trình viên dễ hiểu và dễ kiểm soát nhất.	•	Trước khi các mô hình cao cấp hơn ra đời, thread là cách duy nhất để chạy song song nhiều công việc.b. Hiểu thread sẽ giúp hiểu sâu các mô hình cao cấp hơn	•	Các framework như ExecutorService, ForkJoinPool, RxJava, thậm chí cả async/await… đều sử dụng thread phía dưới.	•	Nếu không hiểu thread, sẽ khó kiểm soát hoặc debug khi gặp vấn đề đồng thời (deadlock, race condition…).c. Hầu hết các hệ điều hành và ngôn ngữ đều hỗ trợ thread	•	Từ Java, C/C++, Python… đến Windows, Linux đều dùng khái niệm thread như “nguyên liệu” cơ bản để xử lý đa nhiệm.3. Lập trình đồng thời = làm việc với nhiều luồng	•	Lập trình tuần tự: Code thực thi từ trên xuống dưới, một luồng duy nhất.	•	Lập trình đồng thời: Có thể có nhiều thread chạy các phần code khác nhau cùng lúc (hoặc đan xen), tăng tốc độ, tận dụng CPU nhiều nhân.4. Thread giúp giải quyết các vấn đề thực tế nào?	•	Xử lý song song: Ví dụ: tải nhiều file cùng lúc, xử lý nhiều request, v.v.	•	Giao diện mượt mà: Ví dụ: UI chạy ở thread chính, các công việc nặng (tải file, đọc mạng…) chạy ở thread phụ, giúp UI không bị đơ.	•	Tận dụng CPU đa nhân: Thread giúp sử dụng hiệu quả nhiều core của CPU hiện đại.5. Những mô hình hiện đại vẫn dựa trên thread	•	Thread pool: Quản lý tập hợp các thread để thực hiện nhiều task liên tục (thay vì tạo/destroy thread liên tục).	•	ExecutorService: Quản lý thread pool trong Java.	•	Future/CompletableFuture: Dùng để xử lý bất đồng bộ, nhưng thực chất vẫn chạy trên các thread.	•	Reactive (RxJava, Reactor…): Ẩn thread đi, nhưng bên dưới vẫn dùng thread.6. Tóm tắt dễ hiểu: Thread là viên gạch đầu tiên của lập trình đồng thời trong Java (và các ngôn ngữ khác). Nếu hiểu thread, bạn sẽ hiểu được tất cả các mô hình cao cấp hơn, đồng thời tránh được các lỗi thường gặp như deadlock, race condition, v.v.---------1. synchronized là gì?   •	synchronized là từ khóa gốc trong Java dùng để đảm bảo chỉ một thread được thực thi đoạn code hoặc truy cập tài nguyên tại một thời điểm.   •	Có thể dùng với phương thức hoặc khối code.2. lock() là gì? (java.util.concurrent.locks.Lock)   •	Lock là interface mới hơn (từ Java 5), cho phép kiểm soát đồng bộ chủ động và linh hoạt hơn so với synchronized.   •	Lớp phổ biến nhất là ReentrantLock.   •	Phù hợp cho các trường hợp nâng cao: thử lock có timeout, lock có thể unlock ở thread khác, v.v.--------1. ThreadLocal	•	class đặc biệt trong Java giúp mỗi thread có “biến riêng”, không chia sẻ với thread khác.	•	Nghĩa là: mỗi thread truy cập vào biến ThreadLocal sẽ thấy một giá trị độc lập, giống như mỗi thread có “bản copy” riêng của biến đó.
